# 文件操作工具集 - 需求规格 (spec.md)

## 1. 背景

代码 Agent 的核心能力是操作本地文件系统。Agent 通过调用文件工具来读取项目结构、查看代码、修改文件，从而完成代码开发任务。

本需求定义第一期需要实现的文件操作工具集，为 Agent 提供基础的文件系统交互能力。

---

## 2. 目标

- Agent 能够浏览项目目录结构
- Agent 能够读取文件内容
- Agent 能够搜索文件内容
- Agent 能够创建和写入文件
- Agent 能够编辑已有文件的指定片段
- 所有文件操作都必须在项目目录范围内，保证安全

---

## 3. 工具清单

| 工具名称 | 功能描述 | 优先级 | 需要用户确认 |
|----------|----------|--------|-------------|
| `list_dir` | 列出指定目录的文件和子目录 | P0 | 否 |
| `read_file` | 读取文件内容，支持分段读取 | P0 | 否 |
| `search_by_regex` | 在项目中按正则表达式搜索文件内容 | P0 | 否 |
| `write_file` | 创建新文件或完全覆盖已有文件 | P0 | 是 |
| `edit_file` | 搜索替换式编辑文件内容 | P1 | 是 |

---

## 4. 详细需求

### 4.1 list_dir - 列目录工具

**功能描述**：列出指定目录下的文件和子目录。

**参数**：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `dir_path` | string | 否 | 相对项目根目录的路径，不传则列出项目根目录 |
| `max_depth` | number | 否 | 递归深度，默认 1（只列当前层） |

**返回**：
- 成功：目录结构的文本表示（树形或列表形式）
- 失败：错误信息

**约束**：
- 遵守 `.gitignore` 规则，忽略被排除的文件/目录
- 最大递归深度不超过 5（防止 Agent 误操作导致遍历整个磁盘）
- 空目录也要明确标识

---

### 4.2 read_file - 读文件工具

**功能描述**：读取指定文件的内容。

**参数**：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `file_path` | string | 是 | 相对项目根目录的文件路径 |
| `offset` | number | 否 | 起始行号（从 1 开始），默认从第 1 行开始 |
| `limit` | number | 否 | 读取行数，默认读取全部 |

**返回**：
- 成功：文件内容文本，带行号
- 失败：错误信息

**约束**：
- 只支持文本文件，二进制文件返回错误提示
- 超过一定大小的文件（如 > 100KB），强制分段读取，Agent 需要多次调用
- 行号从 1 开始
- 如果 offset + limit 超出文件末尾，返回实际能读到的部分

---

### 4.3 search_by_regex - 正则搜索工具

**功能描述**：在项目中搜索匹配正则表达式的内容。

**参数**：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `pattern` | string | 是 | 正则表达式模式 |
| `search_path` | string | 否 | 搜索的子目录，默认整个项目 |
| `max_results` | number | 否 | 最大返回结果数，默认 50 |

**返回**：
- 成功：匹配结果列表，每条包含文件路径、行号、匹配内容
- 失败：错误信息

**约束**：
- 遵守 `.gitignore` 规则，不搜索被排除的文件
- 结果数量超过 max_results 时截断，并提示还有更多结果
- 支持常见编程语言文件，跳过二进制文件
- 正则语法使用 JavaScript 正则标准

---

### 4.4 write_file - 写文件工具

**功能描述**：创建新文件或完全覆盖已有文件。

**参数**：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `file_path` | string | 是 | 相对项目根目录的文件路径 |
| `content` | string | 是 | 要写入的文件内容 |

**返回**：
- 成功：确认信息 + 文件路径
- 失败：错误信息

**约束**：
- **需要用户确认后才能执行**
- 如果文件已存在，会完全覆盖（属于破坏性操作）
- 自动创建不存在的父目录
- 文件路径必须在项目目录内

---

### 4.5 edit_file - 编辑文件工具（P1）

**功能描述**：通过"搜索-替换"的方式编辑文件的指定部分。

**参数**：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `file_path` | string | 是 | 相对项目根目录的文件路径 |
| `old_string` | string | 是 | 要搜索替换的原始字符串 |
| `new_string` | string | 是 | 替换后的新字符串 |
| `replace_all` | boolean | 否 | 是否替换所有匹配项，默认 false（只替换第一个） |

**返回**：
- 成功：确认信息 + 修改后的文件内容摘要
- 失败：错误信息（如未找到匹配、多处匹配但未设 replace_all 等）

**约束**：
- **需要用户确认后才能执行**
- 使用精确字符串匹配（不是正则）
- 如果 `old_string` 在文件中找不到，返回错误
- 如果 `old_string` 有多处匹配且 `replace_all` 为 false，返回错误（提示不明确）
- 编辑前隐含读取校验：确保文件是最新的
- 保持文件末尾换行符的一致性

---

## 5. 安全要求

### 5.1 路径穿越防护
- 所有文件路径必须解析为绝对路径后，校验是否在项目根目录范围内
- 禁止通过 `../` 或符号链接逃出项目目录
- 符号链接需要解析真实路径后再校验

### 5.2 操作分级
- **只读操作**（list_dir / read_file / search_by_regex）：无需确认
- **写操作**（write_file / edit_file）：必须用户确认后执行

### 5.3 其他限制
- 不允许操作隐藏文件（以 `.` 开头的文件/目录）？待定，第一期先允许
- 不允许直接修改 `.git` 目录
- 大文件读取有上限保护

---

## 6. 非目标（第一期不做）

- 文件移动/复制/删除工具
- 批量文件操作
- Git 相关操作（单独的工具集）
- 图片/二进制文件处理
- 文件权限管理
- ripgrep 集成（第一期先用 Node 实现搜索）
